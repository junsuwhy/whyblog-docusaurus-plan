# 1-2. 規劃倉庫命名規範 (`whyblog-content` 和 `whyblog-docusaurus`)

## 描述

確立雙倉庫架構中兩個倉庫的正式命名規範，確保命名清楚反映各自的功能角色，並符合 GitHub 最佳實務。此任務將為後續的倉庫建立和配置奠定基礎。

## 工項 tasks

- [ ] 確認應用程式倉庫命名：`whyblog-docusaurus` ，資料夾為本專案目錄下的`whyblog-docusaurus`
- [ ] 確認內容倉庫命名：`whyblog-content` ，資料夾為本專案目錄下的`whyblog-docusaurus/content`
- [ ] 記錄倉庫命名的設計理念和用途說明，寫到專案目錄下的 `README.md`
- [ ] 為下一個任務（PAT 設定）準備倉庫名稱資訊

## 測試方式

- 在 GitHub 上搜尋確認 `whyblog-content` 和 `whyblog-docusaurus` 名稱可用
- 命名規範清楚區分內容倉庫和應用程式倉庫的功能
- 命名符合 GitHub repository 命名規則（小寫、連字符分隔）
- 兩個倉庫名稱長度適中且易於記憶
