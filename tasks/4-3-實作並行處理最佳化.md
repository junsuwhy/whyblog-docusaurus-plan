# 4-3. 實作並行處理最佳化

## 描述

針對 GitHub Actions 部署工作流程實作並行處理最佳化，包括 npm 依賴快取和建置時間最佳化。主要目標是透過快取機制和並行處理來減少每次部署的建置時間，提升整體系統效能。

根據架構文件 2.architect.md 的「4.1 建置效能最佳化」策略：
- 增量建置：利用 GitHub Actions 快取機制減少重複建置時間
- 並行處理：內容檢出與依賴安裝同步進行
- 資源最佳化：自動壓縮 CSS/JS，最佳化圖片格式

## 工項 tasks

- [ ] 更新 `.github/workflows/deploy.yml` 添加 npm 依賴快取配置
- [ ] 實作 Node.js modules 快取策略 (使用 `actions/cache` 或內建 `cache: 'npm'`)
- [ ] 優化工作流程步驟順序，實現真正並行處理
- [ ] 添加建置時間監控和效能指標收集
- [ ] 配置快取鍵策略確保 package-lock.json 變更時重新建置
- [ ] 測試快取機制在不同情境下的有效性
- [ ] 驗證並行處理對建置時間的改善效果
- [ ] 設定合理的快取保留期限和清理策略

## 測試方式

請執行以下驗證步驟確認任務完成：

### 1. 驗證工作流程檔案
```bash
# 檢查 deploy.yml 是否包含快取配置
cat docusaurus/.github/workflows/deploy.yml | grep -A 5 -B 5 "cache"
```

### 2. 測試快取機制
```bash
# 觸發兩次相同的部署，檢查第二次是否使用快取
# 第一次部署後檢查 GitHub Actions 日誌是否顯示 "Cache not found"
# 第二次部署應該顯示 "Cache restored" 或類似訊息
```

### 3. 建置時間比較
```bash
# 記錄最佳化前後的建置時間
# 預期改善：首次建置時間保持不變，後續建置時間減少 30-50%
# 驗證 npm 安裝步驟時間從約 30-60 秒減少至 5-10 秒
```

### 4. 驗證並行處理
```bash
# 檢查 GitHub Actions 日誌確認步驟是否按預期並行執行
# 確認 "Checkout content repository" 和 "Setup Node.js" 等步驟未阻塞彼此
```

### 5. 功能完整性測試
```bash
# 確認最佳化後的工作流程仍能正常：
# 1. 檢出內容倉庫
# 2. 安裝依賴
# 3. 建置 Docusaurus 網站
# 4. 部署到 GitHub Pages
# 最終網站應正常運作且內容完整
```

### 6. 不同情境測試
```bash
# 測試以下情境的快取行為：
# 1. package.json 或 package-lock.json 變更時應重新安裝依賴
# 2. 僅內容變更時應使用快取
# 3. 長時間未部署後快取過期的處理
```
